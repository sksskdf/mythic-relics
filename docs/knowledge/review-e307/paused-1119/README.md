## 다시 시작하면 할 차례 (총괄의 판단)

1. `0c-ruler`의 고침을 검사해 커밋한다.
2. **빠른 걷기:** 데모 세 신은 흔적의 무리를 이기면 사냥 없이 바로 수호자로, 흔적·귀환의 기세 문턱 0, 화면의 「기세를 모은다」「사냥한다 n/m」 삭제 → 검사 → 리뷰 → QA(393×659) → 휴대폰 판 아티팩트. 사용자가 직접 짚은 것이라 맨 먼저다.
3. 재미 재설계를 확정한다. 방향은 「신을 여는」 방식을 버리고 「신들의 힘을 내가 골라 섞는」 방식이다(조건: 고르는 순간이 2~4분에 한 번, 고르면 화면에서 싸우는 모습이 달라짐, 처음 5분 안에 신의 힘 하나와 고르는 순간 하나, 처치 수로 길을 막지 않음). 확정하면 사용자에게 한 화면으로 알리고 묻지 않고 구현한다.
4. 0C의 가운데 셋(`0c-events`·`0c-combat`·`0c-world`)은 전투·원정의 버그 고침이라 어느 설계로 가든 그대로 간다. 덩어리 1의 갈래 여덟(`spec-0c-1.md` 7.2)은 재설계 결과에 따라 그대로·고쳐 씀·버림을 가른다.
5. 하네스 보강을 확정·구현해 갈래 사이에 합친다. 갈래 워크플로(작성자 → 리뷰어 둘 → 고치는 사람 → QA)를 `.claude/workflows/`에 저장한다.
6. 고친 뒤의 봇 측정과 손 QA는 작성자가 아니라 QA 역할(`playtest-qa`)이 맡는다.
